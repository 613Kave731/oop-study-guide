Java Constructors 👷

A constructor initialises an object when it is created with new. Same name as the class, no return type.

Constructors across my project

    this.name   = name;

Java Variable Scope 🌍

Bro Code · 5:38

Scope = where a variable is accessible. Three scopes: instance (field), local (method/block), static (class-level).

All three scopes in my project

// INSTANCE scope — each Player object has its own copy
private int stamina = 20;      // lives as long as the Player object
private boolean exhausted = false;

// LOCAL scope — exists only during playTurn() execution
public void playTurn(GameState state) {
    Card chosen = chooseCard(state);   // local — gone after method returns
    boolean valid;
    int points = rule.calculatePoints(chosen, state);
}

// STATIC scope — shared across ALL SnookerRule instances
// IGameRule.java (SnookerRule)
static final String[] CLEARANCE_ORDER =
    {"Yellow", "Green", "Brown", "Blue", "Pink", "Black"};
VariableScopeWhy
staminaInstanceEach player has their own stamina
CLEARANCE_ORDERStaticSame order for all games — no need to duplicate per object
chosen, validLocalNeeded only within one method call
rule in GameStateInstanceEach game session may use a different rule
Oral answer: "Variable scope is carefully controlled. stamina is an instance variable — each player has their own pool of 20. CLEARANCE_ORDER is static final because the Yellow→Black clearance order never changes and is shared by all SnookerRule objects. Local variables like chosen and valid exist only for the duration of playTurn()."

Java Object Passing 🏬

Bro Code · 5:13

Java passes object references by value. The method receives a copy of the reference — both point to the same object. Mutations inside the method are visible outside.

GameState is passed everywhere — and mutations propagate

// Player.playTurn() receives GameState by reference
public void playTurn(GameState state) { // 'state' is a reference copy
    ...
    chosen.play(state);   // card mutates the SAME GameState object
    // state.redsOnTable is now decremented — visible to GameController
}

// IGameRule.isValid() also receives the same GameState
boolean isValid(Card card, GameState state);
// SnookerRule can call state.setPendingFoul(7) — mutation seen by controller

Why this matters in my design

  • GameState is the shared "blackboard" — all objects read and write it
  • Cards, rules, and players all receive the same reference → no data copying needed
  • This is the Tell-Don't-Ask principle: we tell the card "play on this state", not "give me your data so I can update the state myself"
Oral answer: "Java passes objects by reference value. When playTurn() calls card.play(state), the card receives a reference to the same GameState. So when RedCard calls state.decrementReds(), that change is immediately visible to GameController and every other object holding that reference. This is how all game state changes propagate without any return values."

Java Super Keyword 🦸‍♂️

Bro Code · 8:09

super refers to the parent class. Used in constructors (super()) and to call overridden methods (super.method()).

super() in constructor chains

// The chain: RedCard → BallCard → Card

class RedCard extends BallCard {
    public RedCard() {
        super("Red", 1);   // calls BallCard("Red", 1)
    }
}

abstract class BallCard extends Card {
    protected BallCard(String colour, int points) {
        super(colour, points);  // calls Card(colour, points)
    }
}

public abstract class Card {
    protected Card(String name, int points) {
        this.name   = name;   // final assignment here — only place
        this.points = points;
    }
}

ActionCard uses super to enforce 0 points

abstract class ActionCard extends Card {
    protected ActionCard(String name) {
        super(name, 0);  // all action cards always 0 pts — enforced here
    }
}
// SafetyCard never has to remember to pass 0 — super handles it
class SafetyCard extends ActionCard {
    public SafetyCard() { super("Safety"); }
}
Oral answer: "super() must be the first line in a constructor if called. The chain is: SafetyCard() → super('Safety') → ActionCard('Safety') → super('Safety', 0) → Card('Safety', 0). The private fields name and points can only be set in Card's constructor — that's why the super chain is mandatory. Without it, name and points would never be initialised."

Java Abstraction 👻

Bro Code · 5:30

Exposing what something does, hiding how. In Java: abstract classes (partial implementation) and interfaces (pure contract).

Abstract classes in my project

// Card — abstract: has shared state + behaviour, but play() must be defined by subclass
public abstract class Card implements IPlayable {
    private final String name;
    private final int    points;
    // toString(), getName(), getPoints() — concrete (inherited by all cards)
    // play(), getDescription() — abstract (each card defines its own)
}

// Player — abstract: has shared state (stamina, hand) but decision is abstract
public abstract class Player implements IScoreable {
    private int stamina = 20;
    public abstract Card chooseCard(GameState state); // MUST be overridden
}

State (fields)YesNo (only constants)
ConstructorsYesNo
Multiple inheritanceNo (one extends)Yes (multiple implements)

Java Encapsulation 💊

Bro Code · 8:27

Bundling data and the methods that operate on it. Private fields + public getters/setters. External code cannot corrupt internal state directly.

Player — textbook encapsulation

// Player.java — ALL fields private
private final String  name;
private final Hand    hand     = new Hand();
private       int     stamina  = 20;
private       boolean exhausted = false;

// Public read access only:
public String  getName()     { return name; }
public Hand    getHand()     { return hand; }
public int     getStamina()  { return stamina; }
public boolean isExhausted() { return exhausted; }

// The ONLY ways to change stamina — both controlled internally:
public void  restoreStamina(int amount) { stamina = Math.min(20, stamina + amount); }
private void reduceStamina(int drain)   {
    stamina = Math.max(0, stamina - drain);
    if (stamina == 0) exhausted = true;  // side effect: exhausted set here only
}

Why reduceStamina() is private

No external code can drain a player's stamina arbitrarily. The only entry point is playTurn(), which calls reduceStamina(rule.getStaminaDrain()) at the end of every turn. This is encapsulation protecting a game invariant.

Oral answer: "The stamina system is the strongest encapsulation example. stamina is private — no external class can set it directly. reduceStamina() is private — only playTurn() can call it. restoreStamina() is public — only used by the stamina challenge. The exhausted flag is only ever set inside reduceStamina(). The entire stamina lifecycle is self-contained inside Player."

Java Copy Objects 🖨️

Bro Code · 7:08

Assigning an object variable copies the reference, not the object. To truly copy: implement clone() or a copy constructor. Shallow copy vs deep copy matters.

Reference sharing in my project

// GameState is shared by reference — NOT copied
Player current = players[turnIndex % 2];
current.playTurn(state);  // state is same object for everyone

// If we did this, it would be a reference copy — NOT a new object:
GameState copy = state;   // WRONG: copy and state point to same object
// Mutations to 'copy' affect 'state' — they are the SAME object

Why my design avoids object copying

  • The game needs a single shared GameState — all players and rules must see the same redsOnTable, same clearanceIndex, same glueActive flag
  • Copying GameState would create divergent game state — a bug
  • The Hand returned by getHand() uses Collections.unmodifiableList() so callers can read the list but cannot add/remove cards from it directly — a form of defensive copying
// Hand.java — defensive copy via unmodifiable view
public List<Card> getCards() {
    return Collections.unmodifiableList(cards);
    // caller can iterate but cannot call add() or remove()
}
Oral answer: "My design intentionally avoids copying objects. GameState is one shared object — all methods receive the same reference. Hand.getCards() returns an unmodifiable view, which is a form of defensive copying — the caller sees the real list but cannot modify it, protecting encapsulation."

Java Interface 🦅

Bro Code · 7:51

A pure contract — defines what a class must do, not how. Allows multiple inheritance of type. Enables polymorphism across unrelated class hierarchies.

Three interfaces in my project

// IPlayable — contract for anything that can be played
interface IPlayable {
    void play(GameState state) throws InvalidMoveException, FoulException;
    String getDescription();
}

// IGameRule — contract for any rule engine
public interface IGameRule {
    boolean isValid(Card card, GameState state) throws InvalidMoveException;
    int calculatePoints(Card card, GameState state);
    default int getStaminaDrain() { return 1; } // Java 8 default method
}

// IScoreable — contract for anything with a score
interface IScoreable {
    int  getScore();
    void addScore(int points);
}

Interface vs Abstract Class — your go-to table

QuestionInterfaceAbstract Class
Can have fields?No (only static final)Yes
Can have constructor?NoYes
Multiple inheritance?Yes — class implements A, B, CNo — class extends only one
Default methods?Yes (Java 8+)Yes (regular methods)
Use caseUnrelated classes sharing a behaviourRelated classes sharing state + partial behaviour
Oral answer: "IGameRule is the most important interface. It defines three methods that every rule engine must implement. Thanks to this interface, Player.playTurn() never imports SnookerRule or ChaosModeRule — it only calls rule.isValid() and rule.calculatePoints() on the IGameRule reference. You can add a new rule class tomorrow and playTurn() works without any changes."

Java Polymorphism 🏁

Bro Code · 6:12

"Many forms" — one interface, multiple behaviours. All four types are present in my project.

1. Inclusion / Subtype Polymorphism

// IGameRule variable holds any concrete implementation
IGameRule rule = new ChaosModeRule();    // or SnookerRule, EnduranceModeRule
rule.isValid(card, state);               // dispatched at runtime to ChaosModeRule

// Card reference holds any card subtype
Card c = new RedCard();
c.play(state);    // dispatched at runtime to RedCard.play()

2. Parametric Polymorphism (Generics)

// Deck works for any Card subtype
Deck<Card> deck = new Deck<>();
T drawIf(Predicate<T> condition) throws EmptyDeckException { ... }

3. Overloading (Ad-hoc / Compile-time)

// Same name, different parameters — resolved at compile time
public  RedCard()                           { super("Red", 1); }
public  ColourCard(String colour, int pts)  { super(colour, pts); }

4. Coercion

// Type narrowing via instanceof in isValid()
if (card instanceof RedCard)    return state.expectingRed();
if (card instanceof ColourCard) return state.lastPlayedRed();
if (card instanceof ActionCard) return true;
Oral answer: "My project demonstrates all four. Inclusion: IGameRule reference dispatches to one of four implementations at runtime. Parametric: Deck<T extends Card> is type-safe for any Card subtype. Overloading: constructors like RedCard() vs ColourCard(String, int) are resolved at compile time. Coercion: instanceof checks in isValid() narrow a Card reference to a specific subtype."

Java Dynamic Polymorphism ✨

Bro Code · 8:52

The actual method called is determined at runtime based on the real type of the object, not the declared type of the variable. Also called late binding or runtime dispatch.

The core example — rule dispatch

// Player.playTurn() — rule is declared as IGameRule (compile-time type)
IGameRule rule = state.getRule();

// At compile time: Java only knows this is an IGameRule
// At runtime: if the player picked Chaos mode, rule is actually ChaosModeRule
boolean valid  = rule.isValid(chosen, state);       // → ChaosModeRule.isValid()
int     points = rule.calculatePoints(chosen, state); // → ChaosModeRule.calculatePoints()

Dynamic dispatch on cards

// Player.playTurn() — chosen is Card at compile time
Card chosen = chooseCard(state);
chosen.play(state);
// If chosen is actually a GlueCard at runtime → GlueCard.play() is called
// If chosen is actually a RedCard at runtime  → RedCard.play() is called
// The code in playTurn() never changes — the behaviour does

Why this is powerful in my project

  • Adding a new card type (e.g., BombCard) never changes playTurn()
  • Adding a new rule (e.g., CustomRule) never changes playTurn() or GameController
  • The system is open to extension without modification — this is the Open/Closed Principle
Oral answer: "Dynamic polymorphism is the heart of my design. playTurn() calls rule.isValid() but never knows which rule is running. If I add a CustomRule tomorrow — new class, no changes to playTurn() or GameController. At runtime the JVM looks at the actual object type and dispatches to the right implementation. This is late binding, and it's what makes the project extensible."

📐 Parametric Polymorphism — Generics

Prof explicitly requires this. Write code once that works for any type satisfying a constraint.

// Deck.java
public class Deck<T extends Card> {
    private final List<T> cards = new ArrayList<>();

    public T draw() throws EmptyDeckException { ... }

    public T drawIf(Predicate<T> condition) throws EmptyDeckException {
        for (int i = 0; i < cards.size(); i++) {
            if (condition.test(cards.get(i))) return cards.remove(i);
        }
        throw new EmptyDeckException();
    }
}
// MagnetCard uses it with a lambda predicate:
Card red = deck.drawIf(c -> c instanceof RedCard);
Oral answer: "Deck<T extends Card> is parametric polymorphism. The bound 'T extends Card' means only Card subtypes can go into a Deck — type safety enforced at compile time. drawIf(Predicate<T>) is also parametric — Predicate is a generic functional interface. MagnetCard calls it with a lambda that checks instanceof RedCard."

1. Snooker Trap Mechanic — new ActionCard subclasses

Two new cards extend the ActionCard inheritance chain, demonstrating that the system is Open for Extension, Closed for Modification (OCP): Player.playTurn() was never touched to support them.

// Card.java — two new ActionCard subclasses
class SnookerTrapCard extends ActionCard {
    public SnookerTrapCard() { super("Snooker"); }
    @Override public void play(GameState state) {
        state.applySnookerTrap();   // sets snookerTrapActive = true
    }
}

class EscapeCard extends ActionCard {
    public EscapeCard() { super("Escape"); }
    @Override public void play(GameState state) {
        // snooker cleared in playTurn() before this is called
    }
}

GameState encapsulates the trap flag:

// GameState.java — snooker trap encapsulated as a private flag
private boolean snookerTrapActive = false;
public void    applySnookerTrap() { snookerTrapActive = true; }
public boolean isSnookered()      { return snookerTrapActive; }
public void    clearSnookerTrap() { snookerTrapActive = false; }

Player.playTurn() auto-resolves the snooker before normal card selection (step 1.5):

// Player.java — snooker check runs before chooseCard()
if (state.isSnookered()) {
    state.clearSnookerTrap();
    int escIdx = -1;
    for (int i = 0; i < handCards.size(); i++) {
        if (handCards.get(i) instanceof EscapeCard) { escIdx = i; break; }
    }
    if (escIdx >= 0) {
        hand.removeCard(escIdx);   // consume EscapeCard — no foul
    } else {
        state.setPendingFoul(4, "snookered with no escape card");
    }
    reduceStamina(rule.getStaminaDrain());
    return;
}
Oral answer: "SnookerTrapCard and EscapeCard both extend ActionCard — pure inheritance. When a SnookerTrap is played, GameState sets snookerTrapActive=true (encapsulation). On the opponent's next turn, playTurn() detects it at step 1.5 and auto-resolves: if they hold an EscapeCard it is consumed (no foul); otherwise a 4-point foul is recorded via setPendingFoul(). The snooker check runs before chooseCard() so the player has no choice — this mirrors the real snooker rule."

2. Guaranteed Hand (Option B) — reuse of Deck.drawIf()

Each player's opening hand is guaranteed to contain at least one RedCard and one ColourCard, so they always have a legal pot option. This reuses the existing Deck.drawIf(Predicate<T>) method — parametric polymorphism in action.

// GameController.java — guaranteed deal uses drawIf() from Deck
private void dealInitialHands() {
    for (Player p : players) {
        dealGuaranteed(p, c -> c instanceof RedCard);     // always 1 Red
        dealGuaranteed(p, c -> c instanceof ColourCard);  // always 1 Colour
        for (int i = 0; i < 3; i++) p.drawCard(deck);      // 3 random
    }
}

private void dealGuaranteed(Player p, Predicate<Card> type) {
    try {
        p.getHand().addCard(state.getDeck().drawIf(type));  // typed draw
    } catch (EmptyDeckException e) {
        p.drawCard(state.getDeck());   // fallback: random card
    }
}
Oral answer: "dealGuaranteed() uses Deck.drawIf(Predicate<T>) which was already in the code for MagnetCard. I reused it here with a different lambda — c instanceof RedCard vs c instanceof EscapeCard in MagnetCard. Same parametric method, different predicate. Zero code duplication."

3. Best-of Match — frame lifecycle in SnookerGUI

The GUI now manages a match of 1, 3, or 5 frames. Frame tracking lives in SnookerGUI (the View), keeping the game engine unchanged.

// SnookerGUI.java — match state (View layer)
private int[]  framesWon = {0, 0};   // [0]=human, [1]=AI
private int    bestOf    = 3;        // 1 / 3 / 5
private boolean frameResultRecorded = false;  // guard against double-count

// Called once per frame end — frameResultRecorded prevents double-counting
if (!frameResultRecorded) {
    frameResultRecorded = true;
    String fw = controller.getWinnerName();
    if (fw.equals(humanPlayer.getName()))  framesWon[0]++;
    else if (fw.equals(aiPlayer.getName())) framesWon[1]++;
}

// Start next frame: reset players, keep framesWon
private void startNextFrame() {
    humanPlayer.resetForNewFrame();   // stamina=20, exhausted=false, hand cleared
    aiPlayer.resetForNewFrame();
    startGame(activeRuleType);        // new GameController + fresh deck
}

Player.resetForNewFrame() is a new public method that accesses private fields (encapsulation within the class):

// Player.java
public void resetForNewFrame() {
    stamina   = 20;
    exhausted = false;

Oral answer: "The match system sits entirely in the View (SnookerGUI), which is correct MVC: the game engine knows nothing about frames or best-of. Each frame starts a fresh GameController with a new GameState and deck. framesWon is tracked in the GUI and displayed in the score panel. frameResultRecorded prevents double-counting when refreshDisplay() is called multiple times after game over."
